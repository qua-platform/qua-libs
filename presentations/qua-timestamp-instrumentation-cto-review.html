The problem

Compiler scheduling is observable.
Experiment source should stay scientific.

01

Operational need

Retrieve the exact start time of each executed play() and measure(), including compiler scheduling and control-flow effects.

02

Developer constraint

Scientists must keep writing normal QUA. Timing diagnostics cannot require wrapper calls, hand-authored labels, or experiment-by-experiment rewrites.

Non-negotiable product requirement

“Give the tool the program I naturally wrote; give me back the timing.”

Engineering journey

Three iterations clarified the real abstraction.

08c Production experiment

Power Rabi error amplification with nested parameter and averaging loops.

08d Manual timing proof

One-shot loops, explicit timestamp streams, conversion, relative analysis, no simulation.

08e Zero-touch reusable tool

Natural QUA body; completed program is cloned and instrumented automatically.

The initially proposed wrapper API was rejected because it moved instrumentation burden into every experiment. That was the correct product correction.

Chosen architecture

Instrument after construction. Execute a clone. Preserve the source.

→
03 / EXECUTE Instrumented clone Add timestamp labels, result analysis streams, and QOP capability metadata.
→
04 / OUTCOME Structured timing results Clock cycles, nanoseconds, occurrence arrays, ordering, and relative offsets.

Developer experience

Natural experiment 
with program() as experiment:
    with for_(n, 0, n < 1, n + 1):
        play("x180", "qubit")
        align("qubit", "resonator")
        measure(
            "readout",
            "resonator",
            demod_process,
        )

# No timestamp_stream. No custom calls. No names.
Timing integration 
from timestamp_tools import TimestampRecorder

# After the program context closes
timing = TimestampRecorder(experiment)

job = qm.execute(timing.program)
results = timing.fetch(job)

rows = results.as_rows(
    reference=0
)
Product property: instrumentation is opt-in at execution time, not embedded in scientific source.

Outcome and data contract

Machine-readable first. Human-readable when needed.

names Automatically generated static-statement identities such as play_0_x180_qubit.
clock_cycles Raw arrays returned by QOP. Loop execution produces multiple ordered occurrences.
nanoseconds Converted arrays using the configured 4 ns clock-cycle duration.
as_rows() Sorted event rows with type, pulse, element, path, occurrence, absolute and relative time.

Risk register

The main risk is compatibility, not concept.

Risk Severity Why it matters Proposed control
Private protobuf dependency High The SDK has no public post-build instrumentation hook. Isolate adapter, pin supported SDKs, serialization contract tests per release.
No hardware proof High Local correctness does not prove QOP compilation and timestamp delivery. Run a minimal OPX acceptance matrix before merge or release.
Result volume in large loops Medium Every statement occurrence creates a timestamp value. Add selection filters and explicit occurrence/stream budgets.
Unsupported pre-instrumented programs Medium Mixed manual and automatic streams can create ambiguous ownership. Current behavior fails clearly; later add an explicit coexistence policy.

Proposed rollout

Move through a hardware-gated beta—not directly to general availability.

P0

Hardware acceptance

Single shot, nested loops, conditional path, pre-existing result streams, and multiple elements.

P1

Compatibility contract

Test supported qm-qua versions, formalize failure messages, and document internal coupling.

P2

Hardening and upstream

Statement filters, stream-volume guardrails, performance benchmark, then promotion into qualang-tools.

Beta exit criteria

Correct timing on target hardware across the acceptance matrix and two supported SDK versions.

Do not promise yet

Universal compatibility with every QUA statement type or unlimited loop-volume telemetry.

CTO decision

Recommendation

Proceed as an experimental, hardware-gated capability.

The developer experience now matches the product requirement. Approve continued investment, conditional on proving the private-SDK adapter against real QOP execution before external release.
